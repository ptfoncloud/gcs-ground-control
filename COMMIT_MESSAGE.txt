Fix command routing, recorder, and validation bugs; expand tests

The console could not arm/disarm or change flight mode at all:
ControlPanel.vue posts to /api/command, but nothing mounted the
router that serves it, so every command uplink 404'd. This fixes
that along with everything else found in a full pass over
backend/, frontend/, and scripts/.

Backend (backend/app/):
- main.py: mount commands + ws routers; remove the duplicate
  /command/* endpoints and the duplicate inline websocket that
  used to shadow routers/ws.py.
- vehicle.py: recorder start/stop state was being reset on every
  single incoming MAVLink message (init moved out of the ingest
  loop into __init__, so recording now actually accumulates
  frames). Sequence-loss tracking extracted into _track_sequence();
  it no longer lets a reordered/duplicate packet rewind last_seq
  and corrupt loss counting for every packet after it. Per-message
  field updates extracted into _handle_heartbeat/_handle_attitude/
  _handle_global_position/_handle_sys_status so tests can call the
  real handlers instead of re-implementing the logic. set_mode()
  now raises on an unrecognized mode instead of silently falling
  back to mode 0. force now threads through to send_arm_command.
  print() replaced with logging.
- schemas.py: CommandRequest.command/mode are now Literal types
  (free 422 validation on garbage input), added the missing force
  field, dropped the dead/unused VehicleCommand class.
- routers/commands.py: passes mode/force through, converts a
  ValueError (bad mode) into an HTTP 400.
- config.py: switched Settings from a plain BaseModel to
  pydantic_settings.BaseSettings - env vars (e.g.
  MAVLINK_CONNECTION_STRING from docker-compose.yml) were being
  silently ignored before this.
- Removed database.py, models.py, routers/telemetry.py, and
  telemetry.db: an orphaned SQLite/SQLAlchemy subsystem nothing
  ever wrote to. Flight history is the CSV recorder.

Tests (backend/tests/):
- test_command_interlocks.py and test_mavlink_integrity.py now
  call the actual production endpoints/methods (POST /api/command,
  VehicleManager._handle_heartbeat, VehicleManager._track_sequence)
  instead of hand-copied reimplementations of the logic under
  test. Added coverage for force-disarm, unsupported-mode
  rejection, and a reordered-packet regression case.

Frontend (frontend/src/):
- New config.js resolves the backend URL from window.location
  instead of a hardcoded localhost:8080, so the console works
  when opened from another machine on the same network as the
  backend.
- App.vue: WebSocket reconnects with capped exponential backoff
  instead of dying permanently on any link drop. Packet-rate is
  now derived from the change in the cumulative packets_rx
  counter over a rolling window instead of counting websocket-
  frame arrivals, which was silently capped at the fixed 20Hz
  broadcast rate.
- ControlPanel.vue: FORCE DISARM now actually sends force:true
  instead of a plain disarm.
- Recorder controls deduplicated out of TelemetryCard.vue (was
  rendered 4x, once per telemetry card) into a single
  RecorderControls.vue that also polls and shows live recording
  status.
- audioCaution.js: oscillator type set to 'square', matching what
  the README already claimed.

Tooling (scripts/):
- mock_mavlink.py: HEARTBEAT/GLOBAL_POSITION_INT/SYS_STATUS are
  now actually gated at 1/10/2 Hz; previously all three fired at
  the loop's full 20Hz regardless of their rate comments.
- record_telemetry.py: converts pitch/roll/yaw to degrees before
  writing - the CSV headers claimed _deg but were getting raw
  radians. WS_URL overridable via GCS_WS_URL env var.

Docs:
- README.md: corrected directory layout, mock_mavlink.py's actual
  path (repo root, not backend/scripts/), and the stale test
  count.

All 15 backend tests pass; frontend builds clean.
